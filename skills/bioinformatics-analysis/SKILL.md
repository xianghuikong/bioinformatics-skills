# 生信分析脚本

将用户的生物学问题转化为可执行、可验证、可追溯的分析。默认用中文沟通，保留软件名、基因标识符和命令原文。尊重项目现有语言、计算平台和已确认的方法。

负责分析方法、脚本实现、执行与结果正确性；成图设计和导出由独立的绘图任务负责。用户只需要脚本时交付脚本和用法，明确其验证范围，不把完整数据计算作为默认前提。用户同时要求分析和绘图时，先完成分析数据与统计结果，再交接绘图；若环境中存在 bioinformatics-plotting，可按需使用，无需为了只做分析而加载它。

## 问题与输入

先检查指定文件、项目说明、脚本和已有结果，识别分析阶段，不自动重跑上游。明确本次问题、分析单位和交付物。

从材料提取物种、参考与注释版本、样本分组、重复、批次、配对关系和对照方向。只询问会影响正确性且无法推断的信息；缺失关键设计信息时，先完成独立的数据检查。

读取文件头与代表性记录，确认格式、压缩状态、维度、缺失值、重复 ID、单位和数据层级。连接表格前核对键及其一对一或一对多关系，连接后报告未匹配数和行数变化。不要静默改名、丢弃记录或将缺失值当成零。

区分基因、转录本、蛋白、同源群和通路层级。ID 转换、去版本号或同工型选择应保留映射，并检查冲突。

## 方法选择

根据用户问题与现有输入选择入口。先说明所选流程、选择依据及本次起止阶段；不要仅凭文件扩展名判断实验类型，也不要默认执行所有模块。

| 问题或输入 | 流程入口 | 先核实的条件 |
| --- | --- | --- |
| 原始测序 reads | 数据质控及任务对应的上游处理 | 测序平台、文库类型、单双端、物种与目标 |
| 组装序列或基因组注释 | 组装评估、注释检查或指定的注释步骤 | 序列版本、注释来源、坐标与 ID |
| 蛋白序列或功能命中表 | 功能注释、证据整合与候选筛选 | 序列单位、数据库版本、命中字段及阈值 |
| 多物种蛋白、同源群或树 | 比较基因组、同源关系或系统发育分析 | 物种映射、同工型规则、树与数据的对应关系 |
| 表达矩阵或定量表 | 设计检查、探索性分析及适用的统计比较 | 数据尺度、归一化状态、样本设计及重复 |
| 候选基因集或排序列表 | 适用的功能富集分析 | 候选生成规则、背景、ID 类型与排序含义 |
| 其他生信任务 | 围绕问题制定专门流程 | 数据生成方式、方法适用条件及验证标准 |

用户只要求审查或修复时，限定在该范围。跨模块任务按依赖顺序连接，明确每一步输入、输出及可接受的检查结果后再进入下一步。

沿用符合问题和输入的已有流程。修改方法时说明原因及其对解释的影响。按安装版本的帮助信息、官方文档或原始方法论文核实参数并记录版本，不凭记忆生成未经核实的参数组合。

以下是按任务选择的决策检查项，不是必须全部运行的流程：

- 基因组与注释：核对参考、坐标约定、contig ID 和注释对应关系；分别记录组装质量、污染证据及注释完整性。
- 功能注释：保留数据库版本、命中来源和阈值，区分计算预测与实验支持。合并证据时记录通过、失败、缺失和冲突，不把多个命中直接计作多个基因。
- 比较基因组：核对物种、同源群、代表序列规则、缺失数据处理与树的来源；评估共享祖先和注释质量差异对比较的影响。
- 表达及其他组学统计：核对输入是否满足模型要求，检查独立重复、配对、批次及设计矩阵可估计性。预先明确比较方向、过滤、归一化与多重检验方案。设计不支持推断时交付描述性结果并说明限制。
- 富集分析：明确候选集、背景集、ID 映射和注释覆盖率，报告实际检验集合及校正方法；背景集应与设计和可检测对象相符。

不要为获得预期显著性反复调整参数。探索性调整应记录理由并与预先指定分析区分。

## 可复现执行

检查环境、依赖、CPU、内存、存储和调度器，遵守用户资源约束，优先使用项目环境。仅为当前任务添加必要依赖。

输入保持只读，结果放在明确的输出目录，避免覆盖已有分析结果。脚本应支持配置输入、输出及关键参数，不写死个人路径、账号或集群名称。

昂贵流程先做代表性的小规模运行，验证参数、格式和资源需求，明确试运行不代表完整结果。调度任务保存 job ID、日志位置和状态；提交成功不等于计算成功。重试前检查失败原因、已有输出及重复提交风险。

保存实际命令、软件及数据库版本、配置、适用的随机种子、日志和退出状态。复用现有环境锁定或工作流机制，不为形式引入新框架。记录输入来源和可行的文件指纹，避免无必要地反复扫描大型原始数据。

## 结果验证

检查退出状态和工具特定的完成标记，再验证输出内容，不能仅以文件存在判断成功。

按任务核对样本数、序列或特征数、ID 完整性、过滤前后数量及异常值。对关键转换抽查原始记录与输出对应关系，验证统计效应方向、单位、比较标签和校正范围。

异常结果先追溯输入、映射、参数和日志。保留真实失败及不确定性，不编造结果或用模拟数据替代真实分析；测试数据必须明确标识。

## 交付

交付请求的结果、可重跑脚本或工作流、必要配置及简明方法记录。记录应足以还原输入、设计、参数、版本和执行方式。

报告实际完成的步骤、发现、验证证据及影响结论的限制，区分尚未运行、试运行、完整执行和已验证的结果。诊断数据作为分析交付的一部分；需要查看诊断图时可调用绘图步骤，不能把图的视觉效果作为分析通过的依据。

### 向绘图部分交接

保留完整结果表，另行输出绘图需要的表格或对象；避免只交付经过显著性筛选的数据。优先采用项目现有格式，并记录以下适用信息：

- 样本和特征的稳定 ID、分组、配对关系与实际分析单位。
- 每个数值列的含义、单位、归一化或变换状态，缺失值与零值的区别。
- 比较名称、方向、效应量、适用的不确定性指标、原始 P 值和校正后 P 值，以及检验和校正范围。
- 基因筛选、排序、背景集或集合定义，避免下游绘图自行重新定义分析对象。
- 生成这些结果的脚本、配置、版本和运行标识。

映射到不同任务时使用相应数据对象，如树文件、注释表或序列比对，而不强制所有结果套用差异表达表结构。仅修改颜色、字体或版式不应触发分析重算；改变统计模型、样本范围或分析过滤条件则应重新生成受影响的分析结果。

若用户要求发布到 GitHub，限定发布文件集合，只提交授权的 skill、代码及文档；不自动加入数据、凭据或私人配置。使用指定仓库和可见性，验证远程提交后再宣称发布完成。


## 脚本实现与运行验收

新建可复用脚本时，将读取与校验、分析计算、结果保存分开，使单步可检查。提供实际可用的运行示例与参数说明；复用已有项目时保持其接口。参数存在多处来源时明确优先级，并保存最终生效配置。对输入单位、比较方向及关键阈值不能使用未披露的默认值。

输入不符合格式、样本与矩阵不对应、参数无效或外部程序失败时，返回明确错误和非零退出状态，避免继续生成看似成功的下游结果。错误信息给出出错文件、字段和可采取的修复方式，不输出凭据。

完成标记只能在输出校验通过后写入。恢复运行时核对输入、配置、软件和脚本是否与已有结果匹配；文件存在不代表可复用。部分失败的多样本任务应记录每个样本的状态，不能将失败样本静默排除后报告全体完成。

每次执行保留紧凑运行记录：运行标识、开始和结束状态、输入引用、实际命令、生效配置、软件版本、输出清单及验证结论。已有工作流提供这些信息时直接复用，不重复创建相同记录。

### 有意义的验收

按变化的实际风险选检查：输入格式和映射变化检查缺失、重复与连接行数；统计逻辑变化核对适用设计及可独立验证的小例子；外部工具封装检查错误是否传播和输出是否完整。测试数据应明确标识，不承诺用小样本验证生物学结论。

区分语法或静态检查、小数据试运行和真实任务完整执行。验证记录写出检查对象、预期条件、观察结果以及通过、警告、失败或未检查状态。零个显著结果可以是有效分析结果；不应为了让验收通过而改变阈值。
